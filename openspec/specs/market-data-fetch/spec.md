# market-data-fetch Specification

## Purpose

定義桌面宿主內建的市場資料抓取：何時抓、怎麼對外連線、產出什麼檔案，以及來源失敗時的行為，
讓小工具與動態桌布不必依賴外部 Python 與排程器，就能持續取得與舊資料層相同格式的資料。

## Requirements

### Requirement: 定時抓取

宿主執行期間 SHALL 在台北時間每日 00:00、06:00、12:00、15:00、18:00 各抓取一輪。每台機器的每個時點 MUST 加上
0 至 5 分鐘的隨機延遲，避免所有安裝同時連線。抓取 MUST 在背景進行，不得阻塞小工具、系統匣與桌布接管。

#### Scenario: 收盤後時點

- **WHEN** 宿主持續執行並跨過台北時間 15:00，前一輪在 14:00 之前開始
- **THEN** 宿主在 15:00 至 15:06 之間開始一輪抓取，完成後資料檔更新

#### Scenario: 抓取期間操作宿主

- **WHEN** 一輪抓取正在等待來源回應
- **THEN** 系統匣選單、設定視窗與小工具仍可正常操作

### Requirement: 啟動與恢復時補抓

宿主啟動時，以及偵測到從睡眠或休眠恢復時（2 分鐘內偵測到），若上一輪開始之後已經過了任一排程時點，宿主 SHALL 在
30 至 120 秒的隨機延遲後補抓一輪。資料檔不存在時 MUST 改用 5 至 15 秒的延遲，讓第一次安裝盡快有資料。

#### Scenario: 隔夜開機

- **WHEN** 電腦前一晚 22:00 關機、隔天 08:00 開機並自動啟動宿主
- **THEN** 宿主在啟動後 2 分鐘內開始補抓一輪（錯過了 00:00 與 06:00）

#### Scenario: 睡眠跨過時點

- **WHEN** 電腦 11:30 進入睡眠、12:30 喚醒，宿主沒有結束
- **THEN** 宿主在喚醒後 4 分鐘內開始補抓一輪

#### Scenario: 首次安裝

- **WHEN** 資料目錄中沒有 `tw_events.json`
- **THEN** 宿主在啟動後 15 秒內開始抓取（不計等待網路的時間），記錄檔有該輪開始的時間

#### Scenario: 未錯過時點

- **WHEN** 宿主在 13:00 重新啟動，上一輪在 12:02 開始
- **THEN** 宿主不補抓，等到 15:00 時點

### Requirement: 抓取間隔下限

兩輪抓取的開始時間 SHALL 至少相隔 60 分鐘；在下限內觸發的時點或補抓 MUST 延後到下限屆滿再執行，不得直接丟棄。
資料檔不存在時不受此限。上一輪**沒有任何來源成功**時（例如首次安裝時網路不通），宿主 SHALL 在 10 至 15 分鐘後重試，
也不受此限；連續失敗時重試間隔加倍，上限 60 分鐘。對同一個主機的連續請求 MUST 至少間隔 2 秒。下限以宿主自己的
抓取紀錄計算，切換資料目錄不會重設。

#### Scenario: 喚醒緊接排程時點

- **WHEN** 宿主 11:40 喚醒後補抓一輪，接著到了 12:00 時點
- **THEN** 12:00 那輪延後到 12:40 之後才開始

#### Scenario: 首次安裝時網路不通

- **WHEN** 首次啟動那一輪所有來源都失敗
- **THEN** 宿主在 10 至 15 分鐘後再抓一輪，不必等到下一個排程時點

### Requirement: 等待網路

每輪抓取開始前，宿主 SHALL 確認網路可連上台灣證交所的主機；連不上時每 20 秒重試，最多等 300 秒。逾時後仍照常抓取
（各來源會失敗並沿用舊資料），並在輸出的 `errors` 加入「啟動時網路等待逾時，改用既有資料兜底」。

#### Scenario: 開機時網路尚未就緒

- **WHEN** 宿主啟動補抓時網路要 40 秒後才通
- **THEN** 該輪等網路就緒才開始抓，輸出的 `errors` 不含網路逾時訊息

### Requirement: 抓取開關與隔離環境

設定 SHALL 提供 `data_fetch`，值為 `"auto"`（預設）、`"on"` 或 `"off"`。`"off"` 時宿主 MUST NOT 發出抓取請求、MUST NOT
寫入 `tw_events.json`，只讀取資料目錄中已有的檔案。`"auto"` 時，若環境變數 `LOCALAPPDATA` 與系統登記的本機應用程式
資料夾不同（驗收腳本以暫存資料夾隔離宿主時就是如此），宿主 MUST 視同 `"off"` 並在記錄檔寫明原因；否則視同 `"on"`。經宿主的設定更新指令變更此設定時 MUST 不需重新啟動即生效；直接編輯設定檔則在宿主下次啟動時生效（宿主只在啟動時讀設定檔）。

#### Scenario: 驗收腳本以暫存資料夾隔離宿主

- **WHEN** 驗收腳本把 `LOCALAPPDATA`、`APPDATA` 指向暫存資料夾、資料目錄放入固定樣本或保持空白後啟動宿主，設定檔沒有
  `data_fetch`
- **THEN** 宿主整段執行期間沒有發出抓取請求，資料目錄的內容與修改時間都沒有改變

#### Scenario: 一般安裝

- **WHEN** 使用者以安裝檔安裝後第一次啟動宿主
- **THEN** 宿主依「啟動與恢復時補抓」開始抓取

#### Scenario: 開發機指向 Python 輸出夾

- **WHEN** 開發者把資料目錄設為 `update_tw_events.py` 的輸出資料夾，並把 `data_fetch` 設為 `"off"`
- **THEN** 宿主只讀取該資料夾的 `tw_events.json`，不改寫它

### Requirement: 輸出檔契約

每輪抓取 SHALL 寫出 `<data_dir>/tw_events.json`：UTF-8、無 BOM、合法 JSON。頂層鍵、子結構的鍵名、型別與語意 MUST
與 `update_tw_events.py` 相同，包括 `updated`、`fetched`、`window`、`counts`、`errors`、`wallpaper_errors`、`sources`、
`macro_meta`、`macro`、`events`、`punish`、`quotes`、`top100`、`top100_date`、`holidays`、`twii_intraday`、`twii_daily`、
`margin`，以及各鍵「何時省略」的條件。`updated` 與 `fetched` MUST 是**本機系統時區**的 `YYYY-MM-DD HH:MM`。寫檔
MUST 先寫暫存檔再以改名取代，讀取端不得讀到半份內容。宿主 MUST NOT 寫出 `tw_events.js`，也 MUST NOT 寫入 Lively
的資料夾。

#### Scenario: 寫檔期間輪詢

- **WHEN** 宿主的資料輪詢恰好在寫檔期間讀取 `tw_events.json`
- **THEN** 讀到的是完整的舊檔或完整的新檔，不會是解析失敗的半份

#### Scenario: 人在其他時區

- **WHEN** 系統時區是 UTC+9，抓取發生在台北時間 15:02
- **THEN** `updated` 是 `…16:02`，事件窗口、休市判定與時點仍以台北日期計算

### Requirement: 與 Python 版行為等價

在相同的來源回應、相同的上一份輸出與相同的「現在時間」下，宿主產出的 `tw_events.json` SHALL 與 `update_tw_events.py`
的產出在 JSON 語意上相等（不計鍵序、縮排、換行與浮點數寫法），僅「刻意改良」所列差異除外。比對前，`errors` 與
`wallpaper_errors` 中每筆訊息 MUST 正規化為「訊息前綴」（例外說明 `{e}` 的部分去掉）；前綴、筆數與順序必須相同。
這 MUST 以錄製的真實回應樣本，加上涵蓋各來源邊界情況的樣本，讓兩邊各跑一次並比對的自動化測試驗證。

#### Scenario: 錄製樣本對照

- **WHEN** 以同一組錄製回應、同一份上一份輸出與同一個凍結時間，分別執行 Python 版與宿主的抓取邏輯
- **THEN** 兩份輸出在正規化錯誤訊息後解析成 JSON 相等

#### Scenario: 昨收取自收盤序列

- **WHEN** 行情回應的 `chartPreviousClose` 是數個交易日前的收盤，收盤序列中有前一交易日的收盤
- **THEN** 漲跌幅以前一交易日收盤計算，與 Python 版相同

### Requirement: 來源失敗時沿用舊資料

任一來源失敗時，宿主 SHALL 沿用上一份輸出中對應的資料，粒度與 Python 版相同：總經整鍵；台股事件依類型分三組（除權息、
股東會、法說會與財報）；處置股依市場；行情逐檔；SOFR、休市日曆、盤中走勢、日 K、券資比各自獨立。失敗訊息 MUST 記入
`errors`；盤中走勢、日 K、券資比的失敗 MUST 記入 `wallpaper_errors`，不得記入 `errors`。

#### Scenario: 上櫃處置股來源失敗

- **WHEN** 上市處置股抓取成功、上櫃處置股來源回 HTTP 500
- **THEN** 輸出的上市處置股為新資料、上櫃處置股為上一份輸出中的上櫃部分，`errors` 多一筆上櫃失敗訊息

#### Scenario: 全部來源失敗

- **WHEN** 一輪抓取中所有來源都失敗
- **THEN** 宿主仍寫出檔案，內容是沿用的舊資料，`updated` 為本輪時間、`fetched` 維持舊值

### Requirement: fetched 只在抓到新資料時刷新

`fetched` SHALL 只在本輪至少一個「計入新鮮度」的來源真正抓到新資料時改為本輪時間。計入的來源與 Python 版相同：總經、
除權息、股東會、非快取命中的市值前百大、法說會（含備援）、SOFR、休市日曆。處置股、Yahoo 行情、盤中走勢、日 K、
券資比，以及當日已算過、直接沿用的市值前百大 MUST NOT 使 `fetched` 刷新。

#### Scenario: 只有行情抓得到

- **WHEN** 一輪中只有 Yahoo 行情成功，其餘全部失敗
- **THEN** `fetched` 維持舊值，小工具照常顯示「已 N 天未更新」

### Requirement: 憑證嚴格驗證

所有 HTTPS 連線 SHALL 使用 Windows 系統憑證庫嚴格驗證；驗證失敗 MUST 視為該來源失敗，不得改以「不驗證」重試。
連線 MUST 沿用 Windows 系統代理設定。

#### Scenario: 憑證無效

- **WHEN** 某來源的伺服器憑證無法通過驗證
- **THEN** 該來源本輪失敗並沿用舊資料，`errors` 記錄失敗，宿主沒有送出任何不驗證憑證的請求

### Requirement: 單一來源異常不中斷整輪

任一來源（含其解析）發生非預期錯誤，或回應中單一列的格式異常，SHALL 只影響該來源：該列被略過，或該來源本輪失敗並
沿用舊資料、記入錯誤清單。其餘來源 MUST 照常抓取，該輪 MUST 照常寫檔，宿主 MUST 照常運作。上一份輸出中某個鍵的型別
不符預期時，該鍵 MUST 視為不存在。

#### Scenario: 總經單列欄位型別錯誤

- **WHEN** 總經回應中有一列的 `forecast` 或 `previous` 是非空且非字串的值（例如數字 `1.5`；「空」照 Python 真值判定：`null`、`0`、空字串視為空字串、保留該列）
- **THEN** 只略過該列，其餘總經事件照常輸出（Python 版此情況會整輪崩潰、不寫檔；本項為刻意改良）

#### Scenario: 某來源解析時發生非預期錯誤

- **WHEN** 處置股的解析程式在處理回應時發生非預期錯誤
- **THEN** 處置股沿用舊資料並記錄錯誤，其他來源照常更新，該輪照常寫檔

### Requirement: 單次抓取指令

宿主 SHALL 支援命令列 `--fetch-once <目錄>`：不啟動小工具、系統匣與桌布接管，也不經過單一執行個體檢查，不受
`data_fetch` 設定與排程紀錄影響、也不改寫排程紀錄；抓取一輪、寫入 `<目錄>/tw_events.json`（該目錄已有的同名檔視為
上一份輸出）後結束。暫存檔名 MUST 每個行程不同，與常駐宿主同時寫同一目錄時不互相破壞。寫檔成功時結束碼
MUST 為 0；寫檔失敗時 MUST 為 1。

#### Scenario: 宿主已在執行時單次抓取

- **WHEN** 宿主常駐中，另執行 `fc-host.exe --fetch-once D:\tmp\out`
- **THEN** 指令在 `D:\tmp\out` 寫出 `tw_events.json` 後以結束碼 0 結束，常駐中的宿主不受影響

### Requirement: 標示資料來源與抓取狀態

設定視窗 SHALL 顯示資料來源與授權：臺灣證券交易所、證券櫃檯買賣中心（依政府資料開放授權條款第 1 版，附條款連結）、
公開資訊觀測站、ForexFactory、Yahoo Finance、紐約聯邦準備銀行。設定視窗 SHALL 同時顯示抓取狀態：上一輪完成時間與是否
有來源失敗；抓取因 `data_fetch` 為 `"off"` 或隔離環境而停用時，MUST 明確顯示「未抓取」與原因，避免使用者在不知情下
停在舊資料。

#### Scenario: 開啟設定視窗

- **WHEN** 使用者開啟設定視窗
- **THEN** 視窗中可以看到上述資料來源清單、政府資料開放授權條款的連結與上一輪抓取時間

#### Scenario: 被判為隔離環境

- **WHEN** 宿主因隔離偵測而停用抓取，使用者開啟設定視窗
- **THEN** 視窗顯示「未抓取：偵測到隔離環境」與如何改為 `"on"` 的說明
